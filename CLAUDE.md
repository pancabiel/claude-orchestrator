# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A local, dependency-light orchestrator for running **multiple interactive Claude Code sessions** at once. Each `claude` runs inside a real pseudo-terminal (`node-pty`) on a tiny Node server; bytes stream over a WebSocket to `xterm.js` in the browser, so you get the full interactive TUI (permission prompts, slash commands). Sessions are grouped by project in a sidebar. The UI opens in its own Chrome/Edge `--app` window. UI strings are in Brazilian Portuguese.

## Commands

```powershell
npm install            # node-pty (ships prebuilt binaries), ws, @xterm/*
node server.mjs        # start server → http://127.0.0.1:4319 (npm start does the same)
```

- **Launch the app window:** double-click `start.vbs` (runs `start.ps1` hidden). It starts the server if the port is down, then opens the `--app` window — **Edge first** (only it exposes Microsoft's neural pt-BR voices to `speechSynthesis`; see `speech.js`), Chrome as fallback. `ORCH_BROWSER` overrides (a substring like `chrome`, or a full path to an `.exe`).
- **Autostart no login:** `start-server.vbs` roda `start.ps1 -ServerOnly` (servidor + `tailscale serve`, sem janela). Um atalho pra ele na pasta Inicializar (`shell:startup`) deixa o orquestrador de pé pro celular sem abrir nada.
- **↻ Reiniciar** (`/api/restart`) spawna um `node server.mjs` detached e sai; o novo re-tenta `listen` enquanto a porta não libera. Não usar `powershell.exe` como intermediário: detached = sem console, e o PowerShell morre na hora.
- **Override the port:** set `ORCH_PORT` (read in both `config.js` and `start.ps1`).
- There is **no build step, no test suite, and no linter.** Browser code is plain ES modules; `xterm.js` is served straight from `node_modules/`.
- First-time setup: `cp projects.example.json projects.json`, then edit it — though projects can also be added live from the UI (see below).

## Architecture

Two halves talking over one local HTTP server (`127.0.0.1` only — it spawns real shells, never expose it).

**`server.mjs` — backend.** A hand-rolled `http` router (no framework) plus a `ws` WebSocketServer on `/api/agents/term`. The core abstraction is an **agent**: a `claude` process in a `node-pty` terminal, held in an in-memory `Map` keyed by a random id. Key behaviors:
- On Windows, `claude` is a `.cmd` shim, so agents spawn as `cmd.exe /c claude …` inside ConPTY.
- Each agent keeps a rolling `buffer` (last `MAX_BUF` chars). The PTY **outlives any socket** — reconnecting replays the buffer, so a page reload reattaches and repaints. Multiple sockets can attach to one agent simultaneously (`agent.sockets` Set).
- **Sessions survive a server restart.** Each agent is snapshotted to `data/sessions/<id>.json` (metadata + scrollback + the Claude Code `sessionId`) — debounced on PTY output, forced on rename/say/exit, and flushed by `shutdown()` (also wired to `SIGINT`/`SIGTERM`/`exit` and called by `/api/restart`, which kills the PTYs so no orphan `claude` holds the session the next process will resume). On boot, `restoreAgents()` turns those files back into **dormant** agents: same id, name, tags and scrollback, but no process. Nothing is respawned eagerly — a restart must not fire ten `claude` at once. Attaching to a dormant agent calls `wakeAgent()`, which respawns with `--resume <sessionId>` (falling back to a fresh session in the same project when there's nothing resumable) and writes a grey note into the scrollback. The `sessionId` comes from the `Stop` hook's POST; without the hook, `resumableSessionId()` guesses from `~/.claude/projects/<slugged root>/*.jsonl` — the transcript born during that agent's lifetime and not claimed by another agent. Snapshots older than `SESSION_TTL` (7d) are dropped at boot; `killAgent()` deletes the file (`forgetAgent`).
- The global `permissionMode` setting (persisted to `data/settings.json`) decides how new agents start: `default` (no flag), `auto`/`acceptEdits` (→ `--permission-mode <mode>`), or `bypass` (→ `--dangerously-skip-permissions`). The legacy `skipPermissions` boolean is kept mirrored (= mode `bypass`) for back-compat. `--resume <sid>` / `--continue` are per-spawn options.
- WS protocol: client sends `{t:"in",d}` / `{t:"resize",cols,rows}`; server sends `{t:"ready"|"data"|"meta"|"say"|"exit"|"error"}`.
- REST: `GET/POST/PUT/DELETE /api/projects` (PUT `?id=` edits name/root/color/group via `updateProject()`, id never changes; DELETE `?id=` removes from the registry only — running agents are untouched), `GET /api/agents/live`, `POST /api/agents/kill`, `PUT /api/agents/meta` (name/tags), `GET/POST /api/agents/say`, `POST /api/agents/open-window`, `GET/PUT /api/settings`.
- **Spoken answers (▶):** each agent spawns with `ORCH_AGENT_ID`/`ORCH_PORT` in its env, which Claude Code's hooks inherit. The `Stop` hook `hooks/orch-say.mjs` reads the session **transcript** (not the screen — the PTY is a redrawing TUI) and `POST`s the round's final answer to `/api/agents/say?id=`, which stores it as `agent.lastSay` and broadcasts `{t:"say"}`. On attach, the stored answer is replayed with `replay:true` so the UI enables ▶ without speaking an old answer. The hook is inert without `ORCH_AGENT_ID`, so plain `claude` sessions are unaffected — and the whole feature degrades to a greyed-out ▶ if it isn't installed.
- **Hub cards:** `GET /api/cards/meta` (board reachable? + columns) and `POST /api/cards` (`{project,title,desc,status,tags}`) append a card to the **central Hub's** `data/board.json`. The Hub serves its board statelessly from disk (reads on every request, atomic tmp+rename writes), so a card written here surfaces in the Hub UI on its next poll. Board path comes from `HUB_BOARD` in `config.js`.

**`config.js` — project registry.** Loads `projects.json` (gitignored, machine-specific paths) or falls back to `projects.example.json`. `PROJECTS`/`PROJECT_IDS` are exported with `let` so `addProject()` / `removeProject()` can refresh the live bindings after writing to disk — project changes apply **without a server restart**. Each project may carry an optional `group` label; `project-groups.js` (shared desktop + mobile) clusters the pickers (＋ Novo menu, ✨ Tarefa chips, mobile chips) by it, groups and projects in alphabetical order, ungrouped ones last under "Outros". In the ＋ Novo menu each project row has ✎ (inline edit form: name, root, color, group) and ✕; the group field is an input with a datalist of existing groups, so typing a new name creates a group. Also exports `HUB_BOARD` (resolved from the `my-hub`/`hub` project's root, override with `ORCH_HUB_BOARD`).

**`orchestrator.js` — frontend (single file, vanilla).** Manages a `terms` Map of local xterm instances and connects each to a backend agent. Two state sources that must stay reconciled:
- `live` — the authoritative agent metadata snapshot, repolled every 3s via `/api/agents/live`.
- `layout` — the **user-controlled sidebar tree** (drag-to-reorder, drag-onto-row/header to group, drop on empty to ungroup), persisted in `localStorage` under `orch-layout`. It is *not* derived from projects — but new sessions **seed** from them: `reconcile()` runs on every render, dropping dead ids (dissolving empty groups) and filing each newly-seen agent into its project's group via `ensureProjectGroup()`, which creates the group on the spot (id `gp-<projId>`, carrying a `projId` field) even for a single session. Groups made by dragging get adopted when their name matches the project. Once a session exists the user can drag it anywhere; reconcile never moves it again.
  - Each group header carries a **＋** that starts another session in that group's project (`newAgent(pid, {groupId})` → `rec.groupId` pins the new agent to *that* group, even if several groups share a project).
- Sessões dormentes (restauradas de um restart) aparecem na sidebar com 💤 e classe `dormant`; clicar reata — `ensureConnected()` reata um `rec` cujo socket caiu, sempre com `term.reset()` antes, porque o attach repinta o scrollback inteiro. Só a sessão **ativa** reata sozinha (`ws.onclose` → retry em 1,5s); as outras esperam o clique, senão um restart acordaria todas de uma vez. `mobile.js` faz o mesmo para a única sessão aberta.
- Terminal gotcha: `term.open()` is **deferred to first mount** — opening on a detached element measures 0×0. A transient `"pending:<key>"` activeId visually selects a session before the server assigns its real id via the `ready` frame.
- **✨ Tarefa** (next to ＋ Novo) opens a composer modal (`openComposer()`): project + depth + intent + optional Hub card → starts a session seeded with a depth-aware opening prompt. Same flow as the mobile `/m` view; both share `task-depth.js`. Seeding is wired into `connect()` via `opts.seedPrompt`.

**`task-depth.js` — shared task-depth logic (desktop + mobile).** A *depth* (`rapido` / `refinar` / `documentar`) is a working style encoded entirely in the session's opening prompt, channeling Matt Pocock's `grill-with-docs` (relentless interview → ADR-style decisions + glossary) and `to-issues` (thin vertical slices). Exports `DEPTHS`, `titleFrom`, `seedPrompt`, and `makeSeeder` (injects a multi-line prompt via bracketed-paste once boot output goes quiet, with a hard fallback; `paste:false` digita cru, para comandos de barra como `/rc`). This is where the card-richness spectrum lives — not in form fields.

**`auto-name.mjs` — nome da sessão pelo assunto (backend).** O TUI se redesenha, então o servidor não lê a caixa de input: `feedInput(agent, d, emit)` reconstrói o **primeiro prompt** a partir do fluxo bruto de teclas (imprimíveis, backspace, sequências ANSI puladas) e entende *bracketed paste* — dentro do bloco colado as quebras de linha são conteúdo, só o Enter de fora confirma (é assim que o prompt semeado pelo compositor/mobile é capturado inteiro, não só a primeira linha). Confirmado o prompt, `coreIntent()` descasca o boilerplate do `seedPrompt` (papel, contexto do card, "Modo **…**"), aplica na hora um nome heurístico e chama `claude -p --model haiku --max-turns 1` (prompt vai por **stdin** — sem aspas em argv, acento intacto no Windows) pedindo um título curto em pt-BR; quando responde, o nome é trocado e empurrado no WS como `{t:"meta"}`. Depois, a **primeira resposta** do Claude (via `setSay`) dispara `refineWithAnswer()` uma única vez — é o que salva prompts vagos ("arruma isso"). Renomear à mão marca `userNamed` e trava qualquer reescrita automática. Timeout de 25s, falha silenciosa → fica a heurística; desliga com `ORCH_AUTONAME=0`, troca o modelo com `ORCH_NAME_MODEL`.

**`speech.js` — "dar play" na resposta (desktop + mobile).** Two halves: `cleanForSpeech()` turns Claude's markdown into something audible (code fences → "bloco de código", paths → basename, markup/emoji stripped — **sem corte de tamanho**: a resposta é falada inteira) and a swappable voice *engine*. The only engine today is the browser's `speechSynthesis` (free, offline; long text is chunked and spoken **one chunk at a time**, chained on `onend` and kept alive — enfileirar tudo de uma vez faz o Chrome perder o fim, e ele ainda pausa a fila sozinho depois de ~15s). **Voice choice is the user's:** `listVoices()` returns the pt-* voices ranked by `PREF` (neural `… (Natural)` / `Online` first), and the pick is persisted in `orch-speak-voice` via `setVoiceId()`; a ⚙ next to ▶/🔊 opens the voice+rate picker (desktop modal, mobile bottom sheet) with a `speakSample()` preview. Which voices exist is a *browser* fact: **Edge exposes Microsoft's neural pt-BR voices, Chrome only sees the Windows SAPI ones** — which is why `start.ps1` prefers Edge. An HTTP TTS plugs in via `setEngine()` — callers only use `speak()` / `stopSpeech()` / `isSpeaking()`. `unlockSpeech()` must run inside a user gesture (iOS/Android) before auto-speaking works. Auto-speak is per-UI (`orch-speak-auto` / `orch-m-speak` in `localStorage`) and, on desktop, only the **active** session speaks — others just get a 🔊 mark in the sidebar (`unheard` Set).

**`index.html` / `styles.css`** — shell that loads xterm UMD globals (`Terminal`, `FitAddon`) then `orchestrator.js` as a module. `index.html` redirects small touch screens to `/m` (append `?desktop` to force the full UI).

**`mobile.html` / `mobile.css` / `mobile.js` — phone-first quick-prompt view (route `/m`).** Built for driving the orchestrator from a phone over Tailscale. Flow: pick a project → pick a **depth** → type the task → *Iniciar*. It optionally creates a Hub card (`POST /api/cards`) and starts a session, then **seeds a depth-aware opening prompt** into the PTY. Notes:
- The full xterm TUI is unusable with a soft keyboard, so input is explicit: a text bar (*Enviar* sends text then Enter) plus control keys (Esc / ▲ / ▼ / Tab / ^C / ↵). xterm is the read/scroll output.
- **Prompt seeding** waits for the boot output to go quiet (hard fallback ~6.5s), then injects the prompt wrapped in bracketed-paste markers (`\x1b[200~…\x1b[201~`) + a delayed `\r`, so multi-line prompts don't submit early.
- **Depth** maps to working style (encoded entirely in the seed prompt, channeling Matt Pocock's `grill-with-docs` + `to-issues`): `rapido` (implement directly), `refinar` (relentless interview to sharpen scope, then implement), `documentar` (interview → ADR-style decisions + glossary → thin vertical-slice phases → implement). The card-richness spectrum the user wanted lives here, not in form fields.
- **📡 Sessão limpa + remote control** (botão abaixo de *Iniciar sessão*): abre uma sessão vazia no projeto selecionado (sem intent, sem card, sem prompt de profundidade) e semeia `/rc` assim que o boot fica quieto, ligando o remote control. Usa o mesmo `makeSeeder`, mas com `paste:false` (`task-depth.js`), porque um comando de barra colado via bracketed-paste vira texto e não abre o comando. Dentro da sessão, a mesma coisa está na tecla `/rc` da barra de controles.
- Reuses the same `/api/agents/term` WS and `/api/agents/live` as the desktop UI; tapping a running session reattaches (no re-seed).
- **▶ / 🔊 no cabeçalho da sessão** — ouvir a última resposta / falar cada resposta assim que chega (ver `speech.js`). Foi pensado para o celular: com 🔊 ligado dá pra ouvir o Claude sem olhar a tela.

**Remote access (Tailscale).** `start.ps1`, after the server is up, runs `tailscale serve --bg $port` if the `tailscale` CLI is present (silent no-op otherwise). This proxies the tailnet (HTTPS, your devices only) to `127.0.0.1:$port` — the server itself **stays localhost-bound**, preserving the never-expose-it invariant while the phone reaches it via the MagicDNS URL.

## Conventions

- Keep it dependency-light and build-step-free; that's the point of the project.
- `projects.json`, `data/`, and `node_modules/` are gitignored — don't commit machine-specific paths.
- User-facing strings are pt-BR; match that when editing the UI.
